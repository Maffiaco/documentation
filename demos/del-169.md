### [QH] [POS] Error boundaries: a crash no longer blanks the app

- Errors are caught at every level (app, screen, section), so a crash only affects its own part and staff can keep working.
- Each fallback screen shows an error code and a Reload/Try again button. The error clears when moving to another screen or order, and is reported to Sentry.
- After a new deploy, POS asks to reload instead of auto-reloading, so orders being entered are not lost.
- Background features (new order alerts, printing, QR orders, menu sync) show a warning banner instead of failing silently. A failed print job is dropped and the user is asked to print again.
- QC can test the fallbacks on `/dev/crash` (staging only).
- Next: the same protection for Biz (back office) and Storefront (web order).
